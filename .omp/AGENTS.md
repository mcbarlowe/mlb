- METHOD TRAP found 2026-09-06 (calibration study, 250 sims on the real 2009-2025 design): applying the analytic one-way-ANOVA moment estimator (`moment_variance_estimate`) to residuals that already absorbed franchise+season biases sigma^2_m DOWNWARD — 99% negative when the truth is exactly 0. Use `moment_variance_from_permutation`, which takes the null expectation from the permutation and measured 51% negative at truth 0. Measured type-I error at nominal 0.05: REML LRT 0.036 (use this), within-franchise permutation 0.024, global permutation 0.000 (badly over-conservative on franchise-demeaned residuals). Power on that design: LRT 0.33 at sigma_m = 1 win, 0.98 at 2 wins. A per-manager career-residual spread compared against an analytic noise SE is subject to the same bias — compare against the permutation null instead (observed 1.225 vs null 1.186 +/- 0.082, z = +0.48, p = 0.31).

- PITCH-LEVEL PITCHER USAGE (the follow-up to the runs-allowed signal): `uv run python scripts/analyze_pitcher_usage_effects.py` (~35 s cold / 5 s cached; caches `data/managers/pitcher_usage_*.parquet` + `leverage_*.parquet`, `--refresh` to rebuild). Builds a 3,018,087-row plate-appearance state table from `mlb.pitches` 2009-2025 in ONE temp table inside a single session (at-bat-start outs/runner flags/scores are the inherited decision state), an empirical leverage index over 5,749 states, and three per-club-season MANAGER DECISION indices: `leverage_alignment` (PA-weighted minus leverage-weighted leak-free pitcher FIP — roster quality cancels by construction, so this is pure allocation), `third_time_share` (starter PAs at 3rd+ time through order = hook speed), `platoon_advantage`. VERDICT 2026-09-06: deployment is NOT the mechanism. All three indices FAIL the contiguity placebo (p = 0.48 / 0.15 / 0.37) despite strong LRT/permutation significance, so they are slow-moving CLUB characteristics, not manager fingerprints (they are highly persistent — season-only out-of-sample slopes +0.55 to +0.71). Mediation is flatly negative: adding all three to the runs-allowed model does NOT reduce sigma_manager (22.33 -> 23.86 runs/162) and adds only 1.3pp of explained variance. Priced out, manager-to-manager variation in all three decisions is worth 4.05 runs/162 in quadrature — 3% of the 22.3 runs/162 manager variance in runs allowed. Bullpen leverage deployment specifically is worth ~1.0 run/162. So the runs-allowed signal is real but its mechanism is NOT measurable pitcher deployment.
- CAUTION on two numbers in that script. (1) `third_time_share` carries a large coefficient (-22.3 runs/162 per SD, i.e. slower hook -> FEWER runs) which is REVERSE CAUSALITY, not a finding: managers leave GOOD starters in longer, so the index is selected on starter quality. Do not read it causally; it is included only to give the mediation test its best possible chance. (2) An empirical per-cell win-probability table is UNUSABLE for leverage: leverage is a difference of two win probabilities, so independent noise in two sparse cells adds — raw cells produced LI 27.8 for "1st inning, down 5, two on" when the truth is under 1. Fixed by shrinking each cell toward a smooth logistic fit (score diff signed to the home side, x inning, sqrt term, outs, base state) with a 200-PA prior, then clipping to LI <= 10 and renormalizing. Sanity check after the fix: the max-leverage state is bottom 10th, 0 out, runner on 3rd, down 1 -> LI 8.95, and extra-inning blowouts sit at 0.

The legacy extraction walked `play["pitchIndex"]` and emitted a row for EVERY referenced `playEvents` entry, but `pitchIndex` also points at `isPitch: false` events — pickoff attempts, pitcher step-offs, and the "Automatic Ball/Strike" events from intentional walks and pitch-timer violations. Those events either carry no `pitchNumber` (so `pitch.get("pitchNumber", 0)` stored 0) or REUSE the preceding real pitch's `pitchNumber`; `pitches_pk` + `ON CONFLICT DO NOTHING` then collapsed the collisions, keeping whichever row COPY reached first. Two defects resulted: 238,769 junk rows parked at `pitch_number = 0`, and 2,340 REAL pitches evicted by an `Automatic %` event that stole their key (evicting the real pitch ~78% of the time). The extraction was fixed by commit `71533db` (2026-08-27) which skips `isPitch is not True`, so games loaded from 2026-08-25 onward are clean — verify with `select count(*) from mlb.pitches where pitch_number = 0` scoped to recent game_dates. The repair re-fetched 2,417 games from StatsAPI and rewrote their pitch rows; all 2,340 evicted pitches are restored (`... where pitch_number > 0 and pitch_call_description like 'Automatic %'` is now 0). Detector for future regressions is in the script's `TARGET_SQL`: pitch rows stopping before the linescore's last inning, `at_bat_index` gaps, final games with no pitches, or `Automatic %` rows at `pitch_number > 0`. NOTE: after the fix, `at_bat_index` gaps are EXPECTED and benign — an at-bat can legitimately contain no pitches (intentional walk, runner caught stealing), so gaps alone are not a defect; 28 still-flagged games were verified pitch-for-pitch against StatsAPI with zero delta.
